# Правила работы над сборником

Основной язык — русский. Источники документа — `main.tex` и `sections/`. Цель — полное, физически корректное изложение программы 1.3.4, пригодное для подготовки к устному экзамену.

## Перед изменением

Прочитать нужный вопрос, соответствующую строку `docs/SOURCES.md`, библиографические записи и относящиеся к задаче замечания. Если проект находится в Git, сначала проверить актуальные изменения и историю. Сохранять чужие правки; не требовать от автора отдельного журнала мелких исправлений.

Commit, push, создание удалённых веток/PR, merge и публикацию выполнять только в пределах явного поручения. Не выполнять разрушительные Git-команды без основания. Личные материалы и инструкции не публиковать; учитывать `.gitignore` и не обходить его принудительным добавлением файлов.

## Содержание и структура

- Сохранять определения, физический механизм, ключевые переходы вывода, смысл и применимость результатов. Не заменять объяснение длинной алгеброй или перечнем формул.
- `\Qhead` содержит название и полную формулировку программы, `\Subhead` — самостоятельный подвопрос. Названия должны соответствовать программе; модели и примеры размещаются внутри ответов.
- Оглавление показывает шесть тем и служебные страницы. Полный список x.y.z строит LaTeX из заголовков; сохранять точные обратные переходы к строкам списка. Не дублировать названия в JSON или генерируемых вручную таблицах.
- Общие `\recap`, `\board`, `\oral`, `\bait`, `\sources` обычно размещаются у группы вопросов. «Удобный вопрос» — 1–2 предложения об уже объяснённой второстепенной детали. Структура ответа и легенда описаны во введении PDF.
- Общие соглашения: exp(+ikr−iωt), преобразование Фурье с +iωt, обратное с 1/(2π); угловые двусторонние спектры; G(f)=2S(2πf). Различать декременты поля и энергии, FWHM и полуширину. Другие локальные соглашения объявлять.

## Источники и связи

- Приоритет: соответствующий курс МГУ → литература программы → другие надёжные источники. Различать лектора и автора студенческой записи. Не выдумывать страницы, формулы, просмотр видео, авторство или прочтение полной книги.
- У содержательной правки сохранять привязку: автор/название, глава/параграф, проверенная PDF- и печатная страница либо фрагмент; URL файла — в библиографии. Различать подтверждённое утверждение, переработку источника и самостоятельный вывод. Последний должен быть воспроизводим по указанным уравнениям и условиям. Неустановленную привязку явно отметить.
- Совпадающие объяснения не размножать: достаточно одного изложения с несколькими ссылками. Полезные альтернативы отмечать кратко с источником.
- Связи «частный случай», «обобщение», «другой вывод», «использование результата» и различия допущений отражать обычными `\label`, `\ref`, `\eqref`, `\hyperref` и комментариями. Сохранять осмысленные метки; при перенумерации обновлять `docs/NUMBERING.md`.
- Сканы хранить отдельно. Фиксировать исходную страницу; различать ошибку OCR, ошибку записи и физическую ошибку, либо указывать неопределённость. Сомнительное место не исправлять молча.
- Не создавать без отдельной задачи сайт, систему метаданных, базу понятий, тотальную разметку или массовое OCR.

## Отметки рецензентов

Не выставлять человеческое принятие самостоятельно. `config/reviews.tex` содержит только явно полученные решения соответствующих рецензентов. После содержательной правки снять устаревшее принятие затронутого текста и отметить это в описании изменения. Значок группы учитывает общий текст и все подвопросы. Типографская правка сама по себе не означает нового физического содержания.

## Сборка и проверка

Обычная сборка: `latexmk -xelatex main.tex`. Нужны XeLaTeX, BibTeX, latexmk, русские переносы и пакеты преамбулы. Шрифты и готовые рисунки включены; Python не является шагом стандартной сборки.

Для агента и CI: `python tools/build.py --all`, `--section 1`, `--question 1.4` или `--question 1.4.2`; `python tools/check.py --compiled --all-sections`. Этим двум инструментам достаточно стандартной библиотеки Python. `tools/figures.py` отдельно требует numpy/scipy/matplotlib; запускать только при необходимости изменить рисунки.

При выборочной сборке внешние номера формул берутся из `build/main.aux`; после изменения их определений сначала собрать полный документ. Для содержательных правок проверить общий PDF, разделы и изменённые вопросы, источники, формулы, знаки, размерности, нормировки, ссылки, библиографию, журналы и вёрстку. Для правок документации достаточно относящейся к ним проверки. Компиляция не доказывает физическую корректность; локальная проверка не доказывает работу GitHub Actions.

README предназначен читателям и участникам; служебные команды остаются здесь. Существенные изменения и открытые ограничения кратко описывать в PR. Не включать в репозиторий сборочные кэши, локальные архивы, чужие книги, сканы, записи и личные ревью.

`radiophysics.pdf` в корне — готовая редакция для читателей, включаемая в репозиторий. Перед выпуском обновлённой редакции собрать и проверить `build/main.pdf`, затем заменить им корневой `radiophysics.pdf`; не подставлять PDF отдельного раздела или вопроса. README должен вести прямо к этому файлу. Артефакты CI служат для проверки промежуточных правок и не заменяют готовый PDF. Публикацию на GitHub выполнять только в пределах поручения.
